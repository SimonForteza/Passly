|Description
|<b>ServicioDeUsuarios</b>: identidad, credenciales y rol global de las personas del sistema.  
+
<b>Usuarios es la raiz del grafo de dependencias</b> y esta anotacion lo convierte en algo que el build verifica. La lista vacia de dependencias permitidas no significa "sin restricciones": significa <i>ninguna</i>. Si manana alguien importa aca cualquier otro modulo del sistema, el build falla con `Allowed targets: none`.  
+
Que Usuarios no dependa de nadie es lo que le permite ser el cimiento de la cadena `eventos -> productoras -> usuarios`: la identidad es lo unico que el resto del sistema necesita sin tener nada que ofrecer a cambio. Si Usuarios llegara a necesitar a otro componente, seria una senal de que ese componente esta mal ubicado — y el build lo diria antes que una revision de codigo.
|Base package
|`com.passly.usuarios`
|Spring components
|_Services_

* `c.p.u.UsuarioService` (via `c.p.u.internal.negocio.UsuarioServiceImpl` -- Implementacion de `c.p.u.UsuarioService`: las reglas del dominio y el limite transaccional.  
+
<b>Package-private a proposito.</b> Spring la instancia igual por reflexion; los demas componentes solo pueden inyectar `c.p.u.UsuarioService`, sin poder nombrar esta clase concreta (CLAUDE.md 4.3, regla 1).)
